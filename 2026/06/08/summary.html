`EXPECT_CALL`로 건 mock이 단락 평가 때문에 실제로는 호출되지 않아 테스트가 의도와 다르게 통과하거나 실패하는 실무 함정을 짚는다는 점이 핵심이다. 2026년 현재도 GTest를 쓰는 C++ 개발자가 if 문 내부 mock 호출을 디버깅할 때 즉시 활용할 수 있는 구체적 사례다.

  • OR(||): 좌변이 true면 우변은 평가되지 않음 — `is_admin`이 true면 `hasPermission()`은 호출 안 됨.
  • AND(&&): 반대로 좌변이 false면 우변은 건너뜀.
  • 함정: 순수 가상 함수 `HasPermission()`을 가진 `PermissionService` mock에 `EXPECT_CALL`을 걸어도, if 식이 단락되면 기대한 호출이 발생하지 않아 mock 기대가 깨진다.
  • 대처: if 조건의 평가 순서와 단락 가능성을 고려해 mock 기대 또는 테스트 입력을 설계해야 한다.

배경 단락 평가는 논리 연산자가 최종 결과 결정에 필요할 때만 두 번째 피연산자를 평가하는 동작으로, 불필요한 작업을 피하는 이점이 있지만 부수 효과가 있는 호출에서는 예기치 않은 누락을 만든다.
